# ForgePilot: MCP servers + Skills

ForgePilot's agent is built with `createDeepAgent` (deepagents 1.13.2). deepagents has **built-in skills support** (`skills` param / `createSkillsMiddleware`) but no MCP support, so MCP tools come via the official `langchain-mcp-adapters` package and get spread into the existing `tools` array.

Decisions (defaults, since no answers): global + per-project skills, stdio + HTTP/SSE transports, MCP tools auto-run (no approval prompt) in v1.

## 1. New dependency
- `npm install langchain-mcp-adapters` (official LangChain adapter; its `MultiServerMCPClient` speaks stdio, Streamable HTTP, and SSE, and returns LangChain `StructuredTool`s that drop straight into `createDeepAgent`'s `tools`).

## 2. Config persistence (`electron/store.ts`)
- Add `mcpServers?: McpServerConfig[]` and `skills?: SkillsConfig` to `PersistedState`, with getter/saver pairs like the existing sandbox config.
- `McpServerConfig`: `{ id, name, enabled, transport: "stdio" | "http" | "sse", command?, args?, env?, url?, headers? }`.
- `SkillsConfig`: `{ enabled: boolean }` (global library dir is fixed at `app.getPath("userData")/skills`; per-project skills live in `<project>/.deepagents/skills/`).

## 3. MCP service (`electron/mcp-service.ts` — new)
- CRUD helpers over the store, mirroring `providers.ts` patterns.
- `getMcpTools(): Promise<StructuredTool[]>` — builds a `MultiServerMCPClient` from **enabled** servers (stdio → command/args/env; http/sse → url/headers), calls `getTools()`, and caches the client keyed by a hash of the config so repeated agent runs reconnect cleanly when config changes.
- `testMcpServer(config)` — connects just to that server and returns ok/error + tool names, for the "Test connection" button.
- Connection failures are caught per-run and surfaced as an agent error event, never crash the run.

## 4. Skills service (`electron/skills-service.ts` — new)
- `listSkills(project)` — scans the global dir and the project's `.deepagents/skills/` for `SKILL.md` files, parses frontmatter (name, description) using deepagents' exported `parseSkillMetadata`, returns `{ name, description, path, source: "global" | "project" }`.
- `createSkill(project, { name, scope })` — scaffolds a new skill folder with a template `SKILL.md` (frontmatter + instructions body).
- `openSkillsFolder(scope)` — shell-open the folder in Explorer.

## 5. Wire into the agent (`electron/agent-service.ts`)
- In `runProjectAgent`, fetch `mcpTools` from mcp-service and pass `tools: [...codeTools, subagentTool, ...mcpTools]` (agent-service.ts:249).
- For skills: wrap the sandbox backend in deepagents' `CompositeBackend(defaultBackend, { "/global-skills": new FilesystemBackend({ rootDir: globalSkillsDir, virtualMode: true }) })`, then pass `skills: ["/.deepagents/skills", "/global-skills"]` to `createDeepAgent` (agent-service.ts:245). deepagents' skills middleware then injects the skill list into the system prompt and reads the full `SKILL.md` on demand. **Verification step during implementation:** confirm `CompositeBackend` routes the `execute` monkey-patch correctly (it delegates to the default backend; if it doesn't, fall back to passing `createSkillsMiddleware` in the `middleware` array with a custom dispatch). Project skills dir may not exist — deepagents handles empty/missing sources gracefully; create it on project activation if missing.
- The system prompt (`buildSystemPrompt`) gets a short note that MCP tools and skills may be available.

## 6. IPC + preload (`electron/main.ts`, `electron/preload.cts`, `src/vite-env.d.ts`)
- New handlers: `mcp:list | mcp:save | mcp:remove | mcp:test`, `skills:list | skills:create | skills:openFolder`.
- Expose `listMcpServers, saveMcpServer, removeMcpServer, testMcpServer, listSkills, createSkill, openSkillsFolder` on `window.forgepilot` with types matching the existing style.

## 7. Renderer UI (`src/App.tsx` + styles)
- Two new modals following the existing `ProviderModal`/`SandboxModal` pattern, opened from header buttons next to Providers/Sandbox:
  - **MCP modal**: list of servers (name, transport, enabled toggle, delete), add/edit form with a transport dropdown — stdio shows command/args/env fields, http/sse show URL/headers — plus "Test connection" showing the discovered tool count, and a saved status dot.
  - **Skills modal**: list of installed skills grouped by Global / Project with descriptions, "New skill" (name + scope → scaffold), and "Open folder" buttons. Skills are plain `SKILL.md` folders, so users can also just edit files directly.

## 8. Verification
- `npm run check` (both tsconfigs) and `npm test` (existing sandbox/agent test) pass.
- Manual smoke: add a trivial stdio MCP server (e.g. a simple echo server), confirm tools appear in a run; create a skill via the modal and confirm the agent's system prompt lists it.
